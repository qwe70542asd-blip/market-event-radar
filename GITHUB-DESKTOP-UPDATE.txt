1. 解壓縮 ZIP。
2. 把 ZIP 內「所有根目錄內容」直接覆蓋本機 market-event-radar repository；不要再多包一層資料夾。
3. 雙擊根目錄 CLEAN-REPO.cmd。它會刪除舊版 v11.4.36～v11.4.38 的 verifier/test helper 與意外巢狀 repository，不會刪正常 production scripts。
4. GitHub Desktop 確認變更後 Commit to main，再 Push origin。
5. 建議 commit：market-event-radar-v11.4.39-stable-core

v11.4.39 核心重做
- Data Verification：stock / ETF 改成完全隔離 adapter。ETF 不會再碰到未初始化的 channel_revenue；股票也不會再誤用 reference_etf。非適用來源 timestamp 明確為 null。
- Data Verification：額外記錄 version_mismatch_sources。上游 channel 尚未全部升版時只標 partial，不冒充全部資料都已同步。
- TPEx 當沖：直接支援目前官方 OpenAPI 真實欄位 DayTradingVolume / DayTradingValueOfBuys / DayTradingValueOfSells，以及三個市場比重欄位；仍保留舊欄位 fallback。
- TPEx 當沖：volume/buy/sell 三個核心欄位必須同時存在才發布，避免半套 schema 被當成有效數據。
- TPEx 股利：統一用同一套 eligible-date 判定。`股東會日期配盈餘/待彌補虧損(元)` 明確認定為金額欄，不再誤當股東會日期。
- TPEx 股利：官方歷史表可正常回傳但本監控期間 eligible=0 時，視為健康零資料，不再把整個 event pipeline 標 warning。
- Release Verification：syntax / strict validation / pytest / HTTP smoke / Chromium 全部先跑，TPEx live contract 最後才跑。TPEx 暫時 5xx 不會再把前面 deterministic 檢查全部 skip。
- TPEx live gate：區分「外部來源暫時 unavailable」與「HTTP 200 且 schema 可用、但 production parser 解析失敗」。只有後者才是 blocking contract failure。
- 保留 Diagnose TPEx live schemas 作為觀測工具，不靠猜測欄位維護 production parser。
