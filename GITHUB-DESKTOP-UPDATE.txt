Market Event Radar v11.4.44 — GitHub Desktop update procedure

This release fixes a repository-overlay problem that allowed old tests/workflows to remain on GitHub even after a newer ZIP was copied over them.

Use this exact order:

1. In GitHub Desktop, fetch/pull the current `main` first.
2. Extract the v11.4.44 full ZIP directly into the repository root. Do not create an extra nested folder.
3. Double-click `CLEAN-REPO.cmd` in the repository root.
4. Wait for: `Repository cleanup complete.`
5. Return to GitHub Desktop and confirm you see deletions as well as modified/new files.
6. Commit with a message such as `market-event-radar-v11.4.44`.
7. Push origin.
8. In GitHub Actions, the first release verification should run the same cleanup check plus the single-writer workflow audit. Do not ignore a red verification run.

Why step 3 is mandatory:
GitHub Desktop copying/overwriting a ZIP does not automatically remove old files that are absent from the new ZIP. v11.4.43 therefore still had older regression tests and duplicate workflow files online. v11.4.44 makes cleanup version-aware so this does not require another hand-maintained deletion list next release.

Expected v11.4.44 workflow topology:
- 16 workflow YAML files total in the release.
- Every live-* data branch has exactly one publishing workflow.
- The old standalone global/Taiwan/news/official/stock-news publishers are deleted.
