# Market Event Radar v11.4.39

## Stable data-contract core rebuild

v11.4.39 replaces the fragile cross-asset verification path and TPEx live-contract handling with isolated, fail-closed adapters.

### Data Verification

- Stock and ETF verification are isolated per asset.
- Optional source rows are created inside each asset adapter; no branch-local variable can leak into another asset class.
- Non-applicable source timestamps are `null` instead of borrowing a channel timestamp.
- `version_mismatch_sources` records upstream channels that have not yet reached the current release version.

### TPEx intraday trading

The current official `tpex_intraday_trading_statistics` schema is handled directly:

- `Date`
- `DayTradingVolume`
- `DayTradingVolumeOfTheMarket`
- `DayTradingValueOfBuys`
- `DayTradingValueOfBuyOfTheMarket`
- `DayTradingValueOfSells`
- `DayTradingValueOfSellsOfTheMarket`

The parser requires volume, buy value, and sell value together. Ratios are optional. Legacy aliases remain fallback-only.

### TPEx dividend plans

- Parser and release gate share the same eligible-date definition.
- The misleading `股東會日期配盈餘/待彌補虧損(元)` field is explicitly excluded from shareholder-meeting date detection.
- A reachable historical table with zero rows in the monitored archive/future window is a healthy zero result, not a parser failure.

### Release verification

Deterministic checks run first: syntax, release hygiene, YAML, strict data validation, tests, HTTP smoke, and Chromium runtime. The external TPEx contract check runs last.

Transient TPEx HTTP/network/JSON failures are recorded as external warnings. A reachable payload with eligible/current rows that the production parser cannot understand remains a blocking contract failure.
