# v11.4.31 Release Audit

## 修正範圍

此版處理 v11.4.30 上線後再次稽核找到的資料與基礎設施問題，包括：首頁 runtime、台股交易日、行情請求量、新聞時間戳、官方分類頁污染、個股符號誤判、資料完整度標示、Actions fan-out、nested repository、live data Git 歷史膨脹與驗證 race visibility。

## 資料誠信

- 台股行情的 `trading_date` 必須來自明確來源日期或官方成交歷史；無法確認時不使用系統今天日期猜測。
- 公司公告發布時間只能由來源日期／時間解析；無法解析的列直接 fail closed。
- 一般官方網頁若缺少發布日期，不列為今日新聞。
- 新聞中的四至六位數字只有在明確股票／證券／代號語境、括號代碼，或附近出現對應公司名稱時才視為股票代碼；單純位於句首也不成立。
- data verification 同時輸出 `trust_overall`、`completeness_status`、`coverage_percent`、`source_snapshots` 與 `stale_sources`。
- 日期公告仍維持 `strict-v11.4.31` 語意防護；歷史回補不算今日新公布日期。
- 舊版 archive 若把未知發布時間寫成 updater 的 `NOW`，v11.4.31 首次更新會識別並移除這類污染列。
- 次要 Yahoo 報價保存實際 market timestamp；不同交易日的官方價與參考價不再被判成 conflict。
- Edge Worker 在預期交易時段但找不到當日 session 時標成 `unconfirmed`，並使用相鄰 K 棒計算前收。
- TPEx `mopsfin_t187ap39_O` 解析器支援官方資料可能使用的合併公司欄位與正式董事會決議日期欄名。

## Actions / 分支

- `update-market-core.yml`：市場核心，5 分鐘排程入口。
- `update-news-batch.yml`：10 個媒體來源用 matrix 批次更新，15 分鐘排程；stock-news 僅在同一批次後彙整，不再由 10 個 workflow_run 重複觸發。
- `update-official-feeds.yml`：公司重大訊息與官方市場公告，15 分鐘排程。
- 舊的單來源／單市場 workflow 保留為 `workflow_dispatch` 手動診斷，不再重複排程。
- `publish_data_branch.sh` 每次使用唯一暫存 orphan branch 後 force push，live branch 是單一快照，不累積舊 JSON commit 歷史。

## 15 分鐘 K

15 分鐘 K 線仍採線上正式行情來源，不得偽造。主站可使用 `live-global-market` 的靜態 K 線 fallback；若部署 Edge Worker，Worker 可提供更頻繁更新。這項部署後驗證維持**非阻擋**：即使 Edge Worker 尚未設定，網站仍可用 GitHub Actions 的正式資料，不得用虛構 K 棒填補。

## 發布前驗證

發布包需通過：Python compileall、全部 JavaScript `node --check`、所有 GitHub Actions YAML 解析、repository layout guard、public data validator、完整 pytest、app shell smoke、HTTP smoke，以及音訊檔掃描。
