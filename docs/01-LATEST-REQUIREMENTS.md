# 市場事件雷達｜最新且唯一有效需求

更新日期：2026-08-02  
基準版本：`v10.8.2-baseline`

本文件取代先前聊天室裡分散的 `v9.x`、`v10.6.x` 與 `v10.7.0` 要求。未列在這裡的舊版說明，不再當成目前規格。

## 1. 產品定位

網站不是模仿 Bloomberg 的複雜終端，而是讓散戶每天花約三分鐘，快速知道：

1. 今天市場最大的風險是什麼。
2. 今天最重要的三件事是什麼。
3. 台股、美股、日股、韓股目前狀況如何。
4. 哪些新聞、政策、財報與產業事件可能影響持倉。
5. 接下來一週到一個月有哪些重要事件。

內容必須比一般事件日曆更嚴謹、來源更清楚，也要比專業終端更容易閱讀。

## 2. 首頁閱讀順序

首頁保持精簡，細節點進去再展開。最新順序如下：

1. 今日市場風險一句話。
2. 今日三件最重要的事。
3. 台股／美股／日韓行情與風險指標。
4. 今日真正的財經快訊與重大消息。
5. 完整事件日曆，搜尋與篩選直接放在月曆區。
6. 台股與美股 ETF 行情輪播。
7. 持倉相關新聞、法人／公告、虛擬貨幣與資料健康等次要區塊。

首頁不得用大量空白卡片、單純裝飾區塊或無資料的 `—` 佔據主要畫面。

## 3. 資料正確性與顯示規則

- 以官方來源、交易所、央行、公司公告與原始媒體文章為優先。
- 資料抓取失敗時，保留最後一次成功資料，並清楚顯示資料時間與狀態。
- 沒有有效資料時顯示「等待第一次成功更新」或「目前無可驗證資料」，不得用 `0.00%`、`+0.0 億`、空字串或破折號冒充即時數字。
- 備援資料必須標成備援／最近資料，不得寫死一個看似即時的時間。
- 新聞必須連到可開啟的原始文章；搜尋頁、媒體首頁與 Google News 中轉網址不能冒充原文。
- 免費行情可能延遲、為最近成交或收盤資料，畫面必須如實標示，不得冒充交易所授權即時行情。
- 個別外資券商分點若需要授權資料，必須清楚說明限制，不得用推測數字補齊。

## 4. 更新頻率與台灣時間

頁面時鐘、更新時間與新聞時間統一使用 `Asia/Taipei`。市場「交易日期」則保留交易所當地日期，不把美股、台股、日股、韓股硬轉成同一日；每個市場顯示目前來源能取得的最後交易日。

| 模組 | 目標行為 |
|---|---|
| GitHub Actions 快速資料 | 最快每 5 分鐘執行一次；實際時間需接受 GitHub 排程延遲 |
| 網頁資料檢查 | 每 30 秒檢查是否有更新；資料沒變時不重繪整頁 |
| 行情 | 每 5 分鐘檢查各市場最後交易日；出現新交易日或同日修正值就更新，來源失敗時保留較新的成功資料 |
| ETF 輪播 | 每組約 8 秒，滑鼠移入或觸控操作時暫停 |
| 虛擬貨幣排行 | 約每 60 秒更新排行；價格變化採平順局部更新 |
| 虛擬貨幣分組 | 每組約 15 秒，不因價格更新整列跳動 |
| 財經新聞 | 以最新成功抓取時間為準，頁面需定時檢查新資料 |
| 法人／公告 | 休市日顯示最近交易日，不能顯示假的當日零值 |

## 5. 市場、股票、ETF 與基金範圍

### 市場範圍

- 台股、美股、日股、韓股。
- 主要指數、波動率、美債殖利率、匯率、黃金、原油與主要虛擬貨幣。
- 台股所有上市櫃股票最終都要可查；美股、日股、韓股也需建立可驗證的證券主檔。

### 證券主檔

不得只靠單一 `theme` 分類。標的至少需要：

`asset_type`、`market`、`exchange`、`industry`、`themes[]`、`currency`、`listing_status`、`aliases[]`、`fund_share_class`、`hedged_currency`、`leverage_type`。

必須能處理代碼、交易所、同名標的、下市、改名、幣別與證券類型。四市場主檔未完成前，只能稱為原型或基礎版。

### ETF／基金

除一般名稱與代碼外，還要有：

- 追蹤指數與主要成分股權重。
- 槓桿／反向屬性。
- 配息、折溢價、規模與成交量。
- 幣別、匯率曝險、避險級別、ISIN 與淨值日期。

## 6. 全產業景氣與市場指標

不能只做製造業 PMI。所有可能影響股票市場的產業與景氣指標都要納入，並採兩層分類：

- 總體：利率、通膨、就業、GDP、零售、消費信心、進出口與匯率。
- 製造與服務：製造業 PMI、服務業 PMI、ISM、新訂單與庫存。
- 半導體／科技：晶片銷售、設備訂單、雲端資本支出、AI 伺服器與消費電子。
- 金融：淨利差、放款、信用風險、保險與資本市場活動。
- 營建／房市：開工、銷售、建照、房價與房貸利率。
- 航運／物流：運價、吞吐量、庫存循環與供應鏈中斷。
- 能源／原物料：油價、天然氣、金屬、農產品與庫存。
- 汽車：銷量、電動車、電池與供應鏈。
- 消費／零售：零售銷售、同店成長、旅遊、餐飲與消費信心。
- 生技／醫療：藥證、臨床結果、醫療支出與政策。
- 其他與股市相關產業：電信、機械、國防、農業等。

首頁只顯示關鍵變化；點進去再看完整指標、前值、預期值、實際值、趨勢、受影響產業與相關標的。

## 7. 個人化與分析功能

- 使用者輸入持有的股票、ETF 與基金後，首頁優先顯示持倉相關新聞與事件。
- 投資組合支援收藏、裝置內保存，以及之後的跨裝置同步。
- 個股分析要有財務體質、產業比較、穩健度雷達圖與重要指標。
- 評分模型必須按產業調整，不能用科技股標準直接評金融、航運或生技。
- 個人化新聞須保留消息來源、時間、影響原因與相關持倉。

## 8. 新聞、重大消息與事件日曆

- 涵蓋央行決策、總經數據、企業財報、月營收、法說會、股東會、股利、除權息、ETF 配息、產品發表、科技活動、政策、關稅、制裁、戰爭、災害與交易中斷。
- 新聞頁需有台灣、國際、官方、券商／投顧公開內容與產業分類。
- 重複或轉載新聞需去重，優先保留官方或原始來源。
- 日曆支援搜尋、日期範圍、地區、事件類型、影響程度與產業篩選。
- 當日大量事件先顯示分類與數量，點入後再看完整清單。

## 9. 法人與官方公告

- 顯示外資、投信、自營商與三大法人日／週／累積資料。
- 顯示最近交易日，休市日不得產生假的零值。
- 支援 TWSE／TPEx 官方資料與個股排行。
- 官方公告需有公司、代碼、時間、類型、摘要與官方來源連結。

## 10. 介面與字體

- 正文以 16px 左右為基準，主要資料 15–17px，輔助文字至少 13–14px。
- 區塊標題約 21–24px；重要數字需明顯大於說明文字。
- 不再大量使用 9–12px 小字，尤其月曆、法人、新聞、虛擬貨幣與資料時間。
- 桌機保持高資訊密度但不擁擠；手機改成單欄或合理分組。
- 所有輪播需可暫停，不得因頻繁重繪造成跳動、位移或閱讀中斷。
- 空資料、備援資料、延遲資料與即時串流必須用文字清楚區分。

## 11. 版本、快取與交付

- 所有頁面、網站安裝資訊、Service Worker、快取名稱與更新流程必須使用同一版本。
- 每次交付前搜尋所有舊版本字串，確認沒有會顯示或控制快取的殘留。
- 不能只做 JavaScript 語法與 ZIP 完整性檢查；必須驗證 GitHub Actions、線上資料、首頁、新聞、行情、法人、手機版與快取更新。
- 每次交付只給一個壓縮包，舊包明確標為淘汰，避免再次混用。

## 12. App 後續方向

網站資料與 App 共用同一份可靠資料來源。App 排在網站資料與功能穩定之後：

- Android 優先。
- 使用 Capacitor 包裝，但不能只做一個單純網址外殼。
- 加入推播、收藏、AdMob、隱私權政策與 Play 商店上架資料。
- iPhone 版本不是第一階段。

## 13. 已淘汰的做法

- 不再使用 `v10.6.1`、`v10.6.2`、`v10.7.0` 當修改來源。
- 不以空資料覆蓋完整備援資料。
- 不使用寫死的假即時新聞時間。
- 不以零值冒充未抓到的行情或法人數據。
- 不只做製造業 PMI。
- 不宣稱目前已完整收錄所有股票、ETF、基金與產業。
- 不只檢查壓縮檔與語法就宣稱「自我檢查完成」。
- 不先做 App、廣告或 iPhone，再回頭修網站資料。
