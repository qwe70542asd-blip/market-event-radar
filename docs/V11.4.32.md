# v11.4.32

本版是 v11.4.31 的 **線上狀態遷移、日期追蹤完整性、資料 archive 與手機執行期整合版**。重點不是再堆資訊卡，而是讓既有 `live-*` 舊狀態安全升級，並把實際部署後才出現的錯誤納入回歸測試。

## 事件與日期追蹤

- BEA／BLS 週期性總經事件改用「系列＋參考期間」tracking key，不再讓每月 PCE、貿易收支等共用同一個 key。
- tracking schema 升級時，BEA／BLS 會執行一次 baseline migration：移除舊版 recurring state 與當日假改期，不把 migration 本身列為今日新公告。
- BEA parser 優先讀正式表格 cell，不再把 `N ews` 一類版面文字混入 tracking key；flat-text fallback 只有遇到下一個完整「發布日期＋時間」才切事件，因此 `Personal Income and Outlays, July 2026` 不再被截斷。
- GDP stage 只接受 `Advance Estimate`、`Second/2nd Estimate`、`Third/3rd Estimate` 本身；不再因標題後段的 `2nd Quarter 2026` 把 Third Estimate 誤判成 Second Estimate。
- BLS fallback 改成 ICS → 各發布項目官方 schedule table → 年度頁。個別頁的 `Reference Month / Release Date / Release Time` 會分欄解析，修正舊版用分隔字串後 regex 永遠對不到的問題。
- 同日同類 manual 與官方 PCE/GDP/貿易事件會 canonical dedupe，官方來源優先；股利事件則分開 decision、payment、ex-right、ex-dividend，避免不同事件種類被合併。

## 歷史事件與股利資料

- `tpex-exdiv-history`、`twse-material`、`tpex-material` 改成增量 archive：新的 daily snapshot 不再把舊已驗證歷史事件洗掉。
- 對同 tracking key 的未來事件，若官方刷新後日期真的變更，才以新 future row 取代舊 future row。
- TWSE TWT49U 歷史除權息改用 `strDate=YYYYMMDD&endDate=YYYYMMDD` 官方區間查詢，避免舊 `date=YYYYMM01` 路徑取不到資料。
- 支援 2026 年後 TWT49U 的 `權/息` 與 `權值+息值` schema；純「息」不再因欄位名稱 substring 同時匹配「權值」與「息值」而誤標成除權息。
- TPEx／TWSE 股利 parser 補官方欄位別名；來源有非空 rows 但 parser 產出 0 時改報 warning，不再顯示假綠燈。

## 台股與籌碼 migration

- `tw-market` 在使用舊 history 前先移除週末、未來日期；偵測到污染時強制重新抓官方歷史。
- 取得官方 verified `trading_date` 後再執行第二次裁切，任何比官方 session 更新的殘留日期都會被移除，因此舊 `2026-08-08` 假交易日不再卡住 v11.4.32 發布。
- `tw-chips` 把舊 `twse:2330` / `tpex:xxxx` key 遷移為純 symbol；舊 top-level institutional schema 轉成 nested structure，`day_trading` 轉成 `day_trade`，並移除週末／未來日期。
- v11.4.32 籌碼 schema 標記為 `symbol-keyed-v2`，workflow 會直接驗證 key 與日期完整性。

## 首頁與手機執行期

- Lightweight Charts 改成 `assets/chart-loader.js` 非阻擋動態載入；第三方 CDN 慢或失敗不再阻止 `shared.js` / `home.js` 啟動，SVG K 線可先獨立顯示。
- library 成功載入後會觸發事件重新 render K 線，無需重新整理頁面。
- 日期公告手機版改成 compact layout，最多先呈現 6 筆；桌機維持較完整列表。
- 市場事件 day dialog 在手機移除重複的上方 summary，保留 tab 計數；主要操作與關閉按鈕提高實際 touch target。
- 大型 `events.json`、`market-kline.json` 等不再整包寫入同步 `localStorage/sessionStorage`；持久 last-good 僅保留小型市場 snapshot，並一次性清理舊版大型 cache key。

## Repository 與部署

舊 GitHub main 曾追蹤 `scripts/.github`、`scripts/assets`、`scripts/data`、`scripts/scripts` 等完整巢狀專案。ZIP 覆蓋不會自動刪除 Git 已追蹤檔案，因此：

1. 解壓 v11.4.32 ZIP 覆蓋 repository 根目錄。
2. 執行 `CLEAN-REPO.cmd`。
3. 在 GitHub Desktop 檢查舊 `scripts/...` 巢狀副本出現大量刪除。
4. 與 v11.4.32 修改一起 Commit / Push。
5. Push 後檢查 release verification、market core、events、tw-chips workflow。

第一輪 `live-events` 會執行 recurring tracking baseline migration；第一輪 `live-tw-market` 會清理舊假 session。BLS 是否仍遭官方 403 只能由部署後 GitHub Actions 實際網路環境確認；即使失敗也必須 fail closed / 保留 last-known-good，不得捏造日期。
