# 逐項測試順序

原則：一次只測一項。上一項未通過前，不同時改下一項，避免不知道是哪個修改造成新問題。

## T01｜GitHub Actions 與 `live-data`

目的：先確認資料更新管線真的能寫出資料。

1. 上傳後確認 `.github/workflows/update-live-data.yml` 顯示 `Update v10.8.3 live data`。
2. 這次 push 會自動跑 `all`，一次建立行情、新聞、公告、法人、事件與標的資料。
3. 若沒有自動執行，到 GitHub → Actions 手動執行，`mode` 選 `all`。
4. 等待完成，確認各更新步驟與發布步驟為綠色；允許標示為可略過的來源顯示警告，但輸出 JSON 必須存在。
5. 檢查 `live-data` 分支已建立。
6. 檢查 `live-data/market-snapshot.json` 不再只有 1 筆有效值，並確認 `news.json`、`announcements.json`、`institutional-history.json` 位於分支根目錄。
7. 開啟首頁後確認資料來源會讀取根目錄檔案，不再要求 `live-data/data/...`。

通過條件：Action 成功、分支存在、主要指數與 ETF 有最後交易日及有效數值，首頁能讀到新聞、法人與公告。  
失敗時要保存：紅色步驟名稱與錯誤畫面；先不改前端。

## T02｜版本與快取

1. 搜尋所有頁面顯示的版本。
2. 確認首頁、新聞、法人、投資組合、資產頁都一致。
3. 確認 `service-worker.js` 與 `assets/sw-register.js` 使用同一版本。
4. 上傳後用一般重新整理與 `Ctrl + F5` 各測一次。

通過條件：不再看到 `10.6.1`、`10.6.2`、`10.7.0` 或 `10.5`；新快取能接管頁面。

## T03｜新聞

1. 檢查 `live-data/news.json` 筆數大於 0。
2. 首頁與新聞頁筆數一致或符合各自顯示上限。
3. 每則新聞有標題、來源、原始文章網址與真實發布時間。
4. 新聞為空時顯示正確狀態，不顯示 `1/1 08:00` 或假即時時間。
5. 點五則不同來源新聞，確認可開啟實際文章。

## T04｜市場行情

1. 台股、美股四大指數、日經、KOSPI 均有有效值。
2. 各市場可以是不同日期，但都必須是該市場來源的最後交易日。
3. 顯示來源、資料性質與最後成功更新時間。
4. 缺值時顯示狀態文字，不顯示假 `0.00%`。
5. 等待至少 60 秒，確認頁面檢查新資料但不會整板閃動。

## T05｜ETF 輪播

1. 台股 ETF 與美股 ETF 均有足夠項目。
2. 每組約 8 秒切換。
3. 滑鼠移入可暫停；手機觸控閱讀不會被立即切走。
4. 名稱、代碼、價格與漲跌不重疊。

## T06｜法人與公告

1. 法人頁顯示最近交易日，不是休市日的假零值。
2. 日／週／累積資料與 TWSE 官方數值一致。
3. 個股排行有資料；沒有授權的券商分點不生成推測內容。
4. 公告連結可開啟官方來源。

## T07｜台灣時間

逐頁測首頁、新聞、法人、公告、事件、行情與虛擬貨幣。頁面更新時間使用 `Asia/Taipei`；市場交易日期保留各交易所當地日期，不可因轉成台灣時間而多一天或少一天。

## T08｜虛擬貨幣

1. 排行約每 60 秒更新。
2. 分組約每 15 秒切換。
3. 價格更新只改數字，不重建整列。
4. 觀察兩分鐘，確認沒有快速跳位、閃爍或閱讀中斷。

## T09｜字體與手機版

測試桌機 1920×1080、一般筆電寬度與手機寬度。

- 正文約 16px。
- 輔助文字至少 13–14px。
- 區塊標題約 21–24px。
- 月曆、法人、新聞與幣圈沒有 9–12px 難讀小字。
- 手機版不出現橫向溢出、文字重疊或按鈕太小。

## T10｜全產業景氣指標

1. 確認不只製造業 PMI。
2. 依最新需求檢查總體、服務、科技、金融、營建、航運、能源、汽車、消費、生技等分類。
3. 每筆有前值、預期、實際、時間、來源、趨勢與影響產業。
4. 點入口後真的進入對應資料，不只是套用總經篩選。

## T11｜四市場股票、ETF 與基金

1. 檢查台／美／日／韓證券主檔。
2. 測試同名、下市、改名、不同交易所與不同幣別。
3. 檢查 ETF／基金的追蹤指數、權重、配息、折溢價、規模與曝險欄位。
4. 未完成前，頁面不得宣稱完整收錄。

## T12｜交付前總驗收

- JavaScript 語法。
- Python 語法。
- JSON 可解析。
- HTML 本機引用存在。
- Workflow YAML 可解析。
- 桌機與手機真實瀏覽器互動。
- GitHub Actions 與線上 JSON。
- Service Worker 更新與舊快取清除。
- ZIP 完整性與根目錄結構。

只有 T01 至 T12 都有可重現證據時，才可標示正式可上傳版。
