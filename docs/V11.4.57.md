# v11.4.58 — Data health and bounded-memory hardening

v11.4.58 將先前分散的 stale、fallback、版本不同步與大型資料載入問題整合處理。

## 核心設計

1. **Single release version source**：部署驗證從 `VERSION.json` 取得版本，Worker `/health` 必須一致。
2. **Compact health index**：`channel-health.json` 僅保存各通道狀態與摘要，不複製完整內容。
3. **Per-item freshness**：ETF／Yahoo 的舊 symbol row 會被抓出，不能靠檔案新 timestamp 掩蓋。
4. **Bounded asset detail**：個股頁只讀一個 0–9 prefix shard，避免同時下載多個全市場歷史檔。
5. **Bounded news memory**：20 日滾動視窗、單來源 180、合併 800；大型 archive 不寫 durable browser last-good。
6. **Fail-closed status**：pending、fallback、partial、stale、circuit-open 都不會被顯示成 fresh。
7. **Two-speed verification**：每 15 分鐘更新輕量 health；每小時做一次完整 cross-source verification。
8. **Last-good shrink guard**：detail shards 先還原前一版再產生，異常大幅縮水會拒絕覆蓋。

第三方網站若暫時 401、改版或封鎖仍可能無法取值；此版本的目標是讓這類情況正確降級、保留最後可信資料且明確標示，而不是偽裝為最新資料。
