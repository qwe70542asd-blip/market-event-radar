# Market Event Radar v11.4.43 release audit

本版不是只看測試綠燈，而是針對使用者實際畫面出現「資料明明存在、首頁卻顯示資料不足」做競速與降級路徑審查。

## 根因與修正

### 1. 首頁 boot timeout 與 loader timeout 互相矛盾
舊首頁最多等待約 4.5 秒，但 GitHub Raw 單一路徑本身可等待超過 5 秒，導致 live data 在 4.5 秒後才成功時，首頁已先採用空 seed。v11.4.43 移除這個一次性 boot timeout，改為 seed 立即掛載、live channel 晚到各自 rerender。

### 2. 台股摘要只初始化一次
舊版後續行情刷新只更新資料時間/K 線/投資組合，沒有重算「盤勢方向、市場廣度、外資方向、成交動能」。現在集中由 `renderTaiwanStatus()` 負責，tw-market 與 tw-chips 任一更新都會重新執行。

### 3. freshness 與 footer 使用錯資料源
台股 freshness 不再混入全球指數時間；`focusUpdated` 不再使用 events.updated_at，而是分別顯示台股行情與法人籌碼時間。

### 4. 新聞 all-or-nothing
12 個新聞通道由逐一完成、逐一 emit 取代整包等待。單一來源慢或失敗時，已成功來源仍會立即顯示。

### 5. 事件與附加新聞耦合
事件頁現在先顯示事件本體，相關新聞晚到再補；high-impact corporate 事件也可進首頁重大資訊。

### 6. 其他頁同類耦合
台股頁、法人頁、投資組合頁與資料狀態頁均改為 progressive update，避免非必要附加來源阻塞核心資料。

### 7. last-known-good 不可靠
所有可用通道加入 IndexedDB last-known-good。Service Worker 對 `/data/` cache key 移除 `t` / `_` query，避免每次 cache-busting 參數不同導致找不到上一份快取。IndexedDB 寫入在背景執行，不延遲 UI 收到 live payload。

### 8. mirror failover 過慢/多餘
Raw → CDN → API 改為 hedged 啟動。後續 mirror 只有在前一路仍未完成時才啟動，一旦已有 valid payload，尚未啟動的 mirror 不會再發 request。

## 瀏覽器 regression

`scripts/browser_smoke.py` 除原本 app-shell 測試外，新增 delayed-live pass：
- tw-market 延遲 5.2 秒；
- tw-chips / events / CNA news 使用不同延遲；
- 最終必須看到 1,244 漲 / 743 跌、外資買超、偏多、量能正常、行情/籌碼時間，以及新聞或 high-impact corporate 重大資訊。

這個測試專門防止「資料最後有回來，但 mounted UI 永遠停在第一次 fallback」再次發生。

## 保留的資料正確性防線

- 公司成立/掛牌日支援 pre-2000 Gregorian 與 ROC compact date，拒絕未來日期及成立日晚於掛牌日。
- global market quote 的 local date 與 session date 不一致時，序列化前 fail closed 並保留上一筆 verified row。
- generic news image 前後端 denylist 一致，JSON-LD object URL 也必須通過檢查。
- MOPS dividend circuit breaker status 以本輪完成後 state 回報。
- TPEx day-trading / dividend-plan parser 仍以先前 GitHub live diagnostic response keys 為準。

## 部署後仍需觀察

- 外部 TWSE/TPEx/MOPS/CTEE 可能暫時 4xx/5xx；本版目標是正確降級與保留 last-known-good，而不是宣稱第三方服務永遠可用。
- 個股 detail 仍一次等待多個核心/補充欄位後完整組裝；它沒有舊首頁「timeout 後永久凍結空狀態」問題，但未來可再拆成 quote-first progressive sections，避免大型補充資料拖慢首屏。
- 深層財務資料覆蓋率仍需由官方來源逐步擴充，不能以跨期間或第三方估值硬補。

## 15 分鐘 K 線策略

15 分鐘 K 屬於部署後資料品質擴充，現階段維持**非阻擋**檢查。只有在部署後取得可驗證來源時才發布；沒有來源證據時**不得偽造** 15 分鐘 K。若 live source 暫時不可用，保留已驗證日 K 並明確標示 unavailable。
