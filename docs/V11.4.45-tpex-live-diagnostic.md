# v11.4.45 TPEx live diagnostic

The TPEx diagnostic remains read-only. It records the live response shape and the production parser result so schema drift can be distinguished from an upstream outage.

## Evidence carried into v11.4.45

The v11.4.40 GitHub diagnostic established two important contracts:

- `tpex_intraday_trading_statistics` returns dated English-key rows (`Date`, `DayTradingVolume`, `DayTradingValueOfBuys`, `DayTradingValueOfSells`). The production parser can read that schema.
- `mopsfin_t187ap39_O` uses the legacy field label `股東會日期配盈餘/待彌補虧損(元)` for a shareholder-meeting date even though the label contains `(元)`. v11.4.45 therefore treats this exact field as a date, while generic monetary-looking fields remain excluded.

## What the workflow records

For each selected TPEx endpoint it captures HTTP attempts, row count, sample keys/values, date parsing, and the current production parser result. A TPEx 4xx/5xx is preserved as diagnostic evidence rather than treated as a diagnostic-program crash.

Workflow: `Diagnose TPEx live schemas`

Artifact: `tpex-live-diagnostic-<run_id>`

Files:

- `tpex-live-diagnostic.json`
- `tpex-live-diagnostic.log`

The v11.4.45 release gate is separate: deterministic tests run first, then reachability-aware live contracts verify reachable official schemas without turning an upstream outage into a false parser diagnosis.
