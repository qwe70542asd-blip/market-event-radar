# v11.4.41 release audit

Target: correct live-data integrity problems observed after v11.4.40 while keeping official-source-first and fail-closed behavior.

Release acceptance criteria:

1. Company establishment/listing dates accept Gregorian and ROC compact formats, but future dates and establishment-after-listing anomalies are rejected.
2. The TPEx dividend-plan legacy shareholder-date header is parsed as a date only by exact official field identity; generic monetary fields are not date candidates.
3. TWSE market day-trading volume and buy/sell amounts are exact sums of official TWTB4U rows; no amount is estimated from price × lots.
4. TPEx institutional amount aliases support official Chinese/English schema drift and publish nothing when required rows are unavailable.
5. Financial-statement ratios with unknown/different period bases are not false conflicts. Point-in-time valuation metrics remain cross-checked.
6. Asset-page trust badges use per-field verification status.
7. MOPS historical dividend backfill uses bounded retries plus a circuit breaker after broad failures; TWSE/TPEx current official dividends remain primary and Yahoo history remains reference-only.
8. Direct media source errors plus a successful history fallback are reported as degraded/fallback, not fully healthy.
9. PWA network-first requests use cache fallback on HTTP failure responses and thrown network errors.
10. Release verification runs deterministic validation/tests/HTTP/Chromium checks before reachability-aware external live contracts.
11. No audio, temporary, nested repository, cache, obsolete verifier/test or build-helper artifacts are included in the release ZIP.
12. `actions/upload-artifact` uses a Node-24-compatible current major.

## Existing non-blocking market-history policy

The prior release policy remains unchanged: **15 分鐘 K** history is a **非阻擋** item verified **部署後** from the live data channel. Missing historical intervals must remain unavailable and **不得偽造** candles from unrelated daily data.
