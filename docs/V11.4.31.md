# 市場事件雷達 v11.4.31

v11.4.31 是資料管線完整性與排程整理版，基於 v11.4.30 的非阻擋月曆與日期公告完整性修正，集中處理行情交易日、新聞發布時間、個股代碼辨識、資料驗證可信度、GitHub Actions 負載與 live data 分支歷史膨脹。

## 主要修正

- 修正首頁 `quoteAgeMinutes()` 缺失造成的 runtime 中斷。
- 台股行情不再把週末／假日當成交易日；報價使用官方可驗證的最近交易日。
- 大盤 K 線依週期套用 TTL，避免每 5 分鐘重抓全部 42 組 Yahoo 圖表。
- live data 載入改為單一 in-flight 請求與循序鏡像 fallback，避免同一資料同時打 Raw、jsDelivr 與 GitHub API。
- 公司重大訊息正確解析民國日期與 5 位數時間，例如 `70004` 解析成 `07:00:04`；解析失敗不再假裝成現在。
- 官方新聞沒有可驗證發布日期就不進入今日新聞；CBC 分類／導覽頁不再被當成重大新聞。
- 個股新聞每次以完整股票主檔重新辨識公司名稱；一般數字即使碰巧是合法股票代碼，也需要明確股票語境才會被接受。
- `affected_markets` 不再殘留 1250 點、1270 家之類的假股票代碼。
- TPEx 股利分派來源改用董事會股利分派 OpenAPI `mopsfin_t187ap39_O`。
- 資料驗證分開呈現「來源可信度」與「欄位完整度」，並記錄每個來源實際驗證的版本／時間與過期狀態。
- ETF 若有持股權重但沒有產業配置，會以官方股票產業主檔計算可追溯的產業配置。
- TPEx 發行股數欄位別名補齊。
- GitHub Actions 合併成市場核心、媒體新聞批次、官方資訊三個主要排程，移除 stock-news workflow fan-out。
- `publish_data_branch.sh` 改成每次建立真正的 orphan snapshot，live-* 分支不再累積資料歷史。
- 新增 `CLEAN-REPO.cmd` / `scripts/cleanup_repo.py`，清理曾誤放在 `scripts/` 下的整套重複 repository；release CI 也會阻止再次發生。
- 第二輪稽核再補上舊版「未知發布時間 = updater NOW」污染資料的遷移清除，避免錯誤時間戳在 archive dedupe 後繼續存活。
- Edge Worker 的前收改用相鄰有效交易 K 棒，避免同一日 regularMarketPrice 與日 K 重疊時產生假 0% 漲跌；交易時窗內若沒有當日 session，狀態改為 `unconfirmed`，不假裝開盤。
- Yahoo 次要參考行情新增實際 `market_at` / `quote_date`；只有官方與參考來源屬於同一交易日時才做價格衝突判定。
- 個股詳情頁不再為了相關新聞下載全部媒體頻道；核心資料與圖表先顯示，事件／個股新聞延後載入。
- TPEx 董事會股利 OpenAPI 同時支援「公司代號名稱」合併欄位與「董事會決議通過股利分派日」正式欄名。
- data verification 排程避開市場核心的五分鐘整點邊界，並保留來源快照時間，降低驗證剛好讀到更新中資料的機率。

## 部署注意

如果目前 GitHub 工作目錄已經存在 `scripts/.github`、`scripts/assets`、`scripts/data`、`scripts/tests` 或 `scripts/scripts`，覆蓋新版檔案後必須先執行根目錄的 `CLEAN-REPO.cmd`，再 Commit / Push。這一步會刪除已知的錯誤巢狀副本，不會刪除正常的 `scripts/*.py` 更新程式。

GitHub Actions 的 cron 屬於平台 best-effort，不保證精準到每一個 5 分鐘刻度；v11.4.31 的做法是減少排程競爭、合併工作流程，並讓資料狀態頁能辨識 stale source，而不是把延遲資料偽裝成即時。
