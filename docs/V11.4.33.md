# v11.4.34

本版是 v11.4.32 的 **成交金額完整性、TPEx 股利解析、個股基本資料驗證與發版執行期防護修正版**。目標是修正 2026-08-09 線上健康檢查仍可確認的資料缺口與 CI 盲點，不用猜測值填補缺失資料。

## 台股成交金額與歷史完整性

- `update_tw_market.py` 的官方月資料回補改成逐月檢查／抓取，不再因「全體歷史筆數已超過門檻」而跳過後續月份。這可修正五月、七月整月缺資料但總筆數仍很多的情況。
- 同一交易日若只有 TWSE component，而同時有已驗證的 TWSE+TPEx 收盤報價合計，完整 quote sum 會優先於單市場 component；單市場資料不得冒充完整市場總成交額。
- 每筆成交歷史新增完整性標記；只有 verified complete total 才參與 5／20／60 日平均。
- `volume_history_complete` 不再只看歷史筆數，而會檢查近期交易 session 是否連續合理；另提供 5d／20d／60d 完整性旗標。
- v11.4.34 第一次執行會強制重新做一次完整月資料回補，即使 v11.4.32 已在同一天留下 `last_full_backfill_date`。
- TPEx 歷史欄位解析增加日期、成交金額與千元單位別名。若官方端仍缺資料，系統維持 partial／incomplete，不自行補造數字。
- ETF 官方名單 fallback 改成 TWSE、TPEx 各自處理；TPEx ETF parser 失敗時可保留其 last-known-good ETF whitelist，不會因 TWSE 成功就失去 TPEx fallback。

## 個股基本資料

- `stock-basics` 產業欄位改成統一正規化：`industry_code`、`industry`、`industry_name` 分開辨識，再輸出文字產業名稱。
- 像 `9103` 這類證券代號或舊 numeric 值不得重新漏回 `industry`／`industry_name`；無法安全辨識時使用 `其他業`，不偽裝成已知產業。
- strict validator 同時檢查 `industry`、`industry_name` 不得為純數字，`industry_code` 若存在只能是合理的短產業代碼。

## TPEx 股利與歷史事件來源

- TPEx 董事會股利 parser 支援 2026 官方欄位變形，包括 `董事會擬議日期`、`董事會決議日期`、`董事會決議通過股利分派日`，並容忍全形括號、斜線與標點差異。
- 公司代號／名稱、現金股利、股票股利欄位增加官方常見別名，避免 API 有數千 rows 卻解析為 0 件。
- TPEx／TWSE 歷史除權息來源若官方回傳的是「合法空集合」，不再誤報 parser warning；只有來源明明含 rows 但 parser 產出 0 時才 warning。
- BLS fallback 增加年度官方 schedule 根頁。若 GitHub Runner 仍遭 BLS 403，維持 warning／last-known-good，不得偽造發布日期。

## 驗證與 CI

- `validate_public_data.py market` 現在會額外檢查：
  - global market 的 `market_at` 日期與 session 一致。
  - top-level session 不得落後於其最新 K 棒。
  - `tw-market.json` quote date 必須等於 verified trading date，且不可是週末假 session。
  - `market-volume-history.json` 不得有重複／未來／週末 session，partial row 不得被標成 complete。
  - metadata 若宣告 20 日成交歷史 complete，必須真的存在足夠且近期的 complete sessions。
- Release verification 新增 Playwright Chromium runtime gate。除了 syntax／HTTP 200，CI 還會真正執行首頁 JavaScript，要求：
  - 無 `pageerror`。
  - 月曆產生 42 格。
  - 月曆標題完成初始化。
  - 市場／股利雙模式按鈕可切換。
- Playwright 使用本地 seed 並封鎖外部 HTTPS，讓 release runtime test 不依賴第三方即時服務是否短暫可用。
- Cloudflare Worker 部署 workflow 移除 job-level `secrets` 條件。未設定 Cloudflare secrets 時變成可解釋的成功 no-op；有設定才進行 build／deploy。

## Repository 清理與部署

GitHub 上若仍追蹤舊 `scripts/index.html`、`scripts/assets/`、`scripts/data/`、`scripts/tests/`、`scripts/scripts/` 等巢狀 repository 副本，單純解壓覆蓋 ZIP 不會刪除它們。

1. 解壓 v11.4.34 ZIP，覆蓋本機 repository 根目錄。
2. 執行根目錄 `CLEAN-REPO.cmd`。
3. 在 GitHub Desktop 確認上述舊巢狀路徑顯示為 deletions。
4. 與 v11.4.34 變更一起 Commit / Push。
5. Push 後確認 release verification 綠燈，再檢查 market core、events、stock basics 等 live workflow。

沒有可信來源時，成交量、股利日期、歷史事件與 K 線都必須 fail closed；缺資料可以明確顯示不完整，但不得以推測數字或日期補空白。
