# v11.4.52 — 完整性防回歸

本版不是再改版面，而是針對「新功能／效能調整把原本完整資料縮成部分資料」做系統性防護。

## 本次一併查出的同類風險

1. **前端只判斷 JSON 有資料，不判斷是否突然少掉大半**  
   live branch 只要回傳一筆非空資料就可能被接受，甚至寫成瀏覽器 last-known-good。現在對事件、資產主檔、個股基本面、ETF 詳情、月營收、股利歷史、驗證資料、K 線、成交量歷史、法人籌碼、第二參考資料加入「災難性縮水」比較；若相較瀏覽器上次完整資料突然大幅減少，拒絕覆蓋並沿用 last-known-good。

2. **空集合 + updated_at 以前會被當成有效資料**  
   這會讓爬蟲失敗卻仍更新時間戳時，整個區塊看起來像正常更新但內容消失。現在陣列／items 型資料必須真的有內容才算可用。

3. **事件更新器只擋完全 0 筆，擋不住「幾千筆縮成幾十筆」**  
   現在事件 archive 若非明確重建流程卻一次縮掉 30% 以上，直接拒絕發布。

4. **其他長期資料通道沒有共用防縮水閘門**  
   `write_payload()` 現在對大型主檔／歷史資料做寫入前比較。既有資料至少 100 筆時，新資料若掉到 45% 以下，工作流程直接失敗，不覆蓋 live branch。

5. **data-verification 更新流程原本沒有先還原自己的上一版**  
   因此即使新增共用防縮水閘門，也沒有上一版可比較。現在會先 restore `live-data-verification` 再產生新版。

6. **secondary-reference 與 market-volume-history 原本繞過共用 writer**  
   兩者已改走 `write_payload()`，同樣受到防縮水保護。

7. **Service Worker cache namespace 還停在 v11.4.50**  
   雖然 v11.4.51 靜態資源帶版本 query，但舊 namespace 仍可能留下跨版殘留。v11.4.52 改成獨立 `market-event-radar-v11-4-52` cache，啟用時清掉舊 cache。

## 保留不動的既有功能

- 完整 `live-events/events.json` 為事件月曆唯一權威資料。
- 首頁重大資訊 1 大 + 3 小等高版型。
- 日期事件不捏造 09:00。
- EU / UK 篩選。
- 上市 + 上櫃外資方向、融資券、當沖與既有市場欄位。
- 新聞多來源、個股頁、ETF 詳情、月營收、股利歷史、資料驗證、K 線與成交量歷史。
- Cloudflare Worker schema gate、午夜換日與 PWA 更新機制。
