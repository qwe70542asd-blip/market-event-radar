# v11.5.0 Architecture / Conflict Audit

## 已移除的舊系統衝突

1. 首頁直接下載完整 assets/events/chips/dividend 歷史檔。
2. 法人頁直接下載完整 tw-chips + Yahoo 詳細資料。
3. portfolio / tw-market / stale guard 仍使用完整 tw-market 舊路徑。
4. date-alerts 與首頁各自抓完整 events，形成重複資料來源。
5. 個股 detail shard 同時存在舊一碼與新分片格式。
6. `mobile-global-quick-nav` 舊動態導覽注入邏輯仍殘留於 shared.js/CSS。
7. 未知純數字產業分類可直接跑到 UI。

## v11.5.0 新資料流

完整來源資料仍由既有 24 個 isolated live branches 保存；前端不直接消費大部分完整 archive。

`source branches -> update-data-verification -> compact frontend indexes -> live-data-verification -> browser`

首頁與主要列表只讀 compact indexes。完整 archive 留給背景驗證、歷史資料與必要的按需 fallback。

## 前端 payload budgets

- home-assets.json <= 800 KB
- home-events.json <= 2 MB
- tw-market-compact.json <= 2 MB
- tw-chips-compact.json <= 4 MB

Budget 在 `update-data-verification.yml` 生成 live compact files 後立即驗證；超過即不發布該批資料。

## 仍屬外部資料品質問題，不應被 UI 假裝正常

- 法人來源不同交易日：降級，不混成同一交易日判讀。
- Yahoo per-item stale：只能做補充，不可覆蓋官方新資料。
- MOPS circuit-open：股利資料標 degraded，保留 last-known-good。
- cross-source conflict：由 data-verification / channel-health 顯示，不用「有值」當成「已確認」。

## Release 原則

外部來源無法保證永遠 0 故障；本版要求的是：
- 0 個已知新舊前端資料契約衝突。
- 0 個完整大型 archive 作為主要頁面 boot dependency。
- 0 個未知數字產業代碼直接呈現。
- 0 個重複 mobile quick-nav owner。
- stale / partial / degraded 不得被標成 fresh。
