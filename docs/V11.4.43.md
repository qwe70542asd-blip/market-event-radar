# v11.4.43 — Progressive Live Resilience

This release removes the frontend boot race that could display empty/stale cards even after verified live data had arrived.

## Progressive rendering

- homepage market, chips, events, news, assets, dividend and global-market channels update independently;
- Taiwan market status rerenders whenever `tw-market` or `tw-chips` arrives;
- news sources stream independently instead of waiting for all publishers;
- event detail no longer waits for related-news channels;
- Taiwan market, institutional, portfolio and data-status pages render core data before optional enrichment;
- high-impact corporate events are eligible for the homepage featured brief.

## Last-known-good resilience

- all usable channels can be retained in IndexedDB;
- cache persistence runs in the background and does not delay live rendering;
- live mirrors use hedged failover and stop launching later mirrors after a valid result wins;
- service-worker data cache keys ignore cache-busting `t` / `_` query parameters and non-OK network responses fall back to the previous cache.

## Correctness carried forward

- preserve legitimate pre-2000 company dates and validate compact Gregorian/ROC dates;
- reject impossible establishment/listing date combinations;
- reject global-market quote/session timestamp mismatch before serialization;
- keep frontend/backend generic-news-image filtering aligned;
- report MOPS circuit-breaker state after each run;
- retain schema-backed TPEx day-trading and dividend-plan parsing.

## Regression coverage

GitHub Chromium release verification now includes a delayed-live test where Taiwan market data arrives after the old 4.5-second boot cutoff. The mounted page must eventually show real breadth, foreign flow, volume momentum and featured information rather than remain on a seed placeholder.
