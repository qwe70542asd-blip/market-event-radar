# v11.4.30 月曆啟動與日期異動完整性修正

- 首頁不再等待所有行情、新聞與事件來源完成後才建立月曆；各資料源都有啟動逾時備援。
- `events.json` 線上通道較慢時，先用內建 seed 建立月曆，線上事件完成後再原地刷新。
- 「今日新公布日期」先顯示可用 seed，不再永久停在「讀取中」。
- 事件產生器只把真正的未來新日期與真正改期列為日期提醒。
- 新掃到的歷史資料不算 `new-date`。
- 同一追蹤鍵的上一個週期已經發生時，下一個週期視為新事件，不誤標 `date-changed`。
- 重大訊息若只是當日財報／公司公告本身，不再冒充「新公布日期」；只有明確標示未來日期的事件才進日期提醒。
- 單一來源若因 parser／tracking-key 變更瞬間產生大量異動，會觸發來源級 surge guard，當次視為基準更新而不是通知洪水。
- 前端再做一次完整性篩選，舊 `live-events` 尚未更新時也不顯示過去日期或不合理跨期改期。
- `events.json` metadata 新增 `announcement_integrity: strict-v11.4.30` 與被抑制來源清單。
