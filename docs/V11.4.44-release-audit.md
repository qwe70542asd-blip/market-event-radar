# Market Event Radar v11.4.44 consolidated release audit

## Why this release exists

v11.4.44 is a cleanup/reliability release. The audit did not stop at the first visible failure; it checked the current GitHub Actions failure history, the live-branch publication topology, Taiwan quote/history date handling, stale files left by overlay releases, static application references, local data schemas, syntax, tests and HTTP app-shell loading.

## Root causes found and fixed

### 1. Overlay updates left obsolete files in GitHub

The packaged v11.4.43 test suite contained 256 tests locally, while the GitHub release-verification run discovered 335 tests. GitHub still contained older `test_v11_4_39_*`, `test_v11_4_40_*`, `test_v11_4_41_*`, older verifiers, old deletion manifests and `apply_v11_4_36.py`.

One stale v11.4.41 service-worker assertion caused the v11.4.43 release-verification run to fail even though the current package's own tests passed.

**Fix:** `scripts/cleanup_repo.py` is now version-aware instead of maintaining a hand-written deletion list. It automatically detects/removes obsolete versioned tests, verifiers, deletion manifests, old patch scripts, accidental nested repo copies and the redundant workflows removed in this release. `CLEAN-REPO.cmd` calls that single cleanup engine. Release verification runs the same engine with `--check`, so stale overlay files cannot silently return.

### 2. Fifteen duplicate live-branch writers could race each other

The previous tree had aggregate schedulers and standalone workflows that could both force-push the same `live-*` branch under different concurrency groups. A manual/push-triggered standalone run could therefore race the aggregate run.

**Fix:** removed 15 redundant publishers and kept one authoritative writer per live branch:

- global + Taiwan market: `update-market-core.yml`
- all media channels + stock media: `update-news-batch.yml`
- company disclosures + official notices: `update-official-feeds.yml`

A new `scripts/audit_workflow_publishers.py` gate scans all workflows and fails if any `live-*` branch has more than one writer.

### 3. Taiwan quote session and turnover-history date were incorrectly coupled

The previous selector used `source_dates or fetched_dates or retained_dates`. In Python that selects the first non-empty list rather than the union. A partial/stale quote date could therefore override a newer verified history date. GitHub then intermittently failed the `Validate verified trading date` step.

**Fix:** quote-session freshness and turnover-history freshness are now separate concepts. A retained quote snapshot keeps its original trading date; verified history may progress independently. History rows are no longer deleted simply because one quote endpoint is stale.

### 4. A one-exchange response could pass the old global row-count test

The old safeguard only required `len(rows) >= 100`. TWSE alone can exceed 100 rows, so a TPEx outage could still publish a TWSE-only market snapshot and silently remove TPEx from breadth/turnover calculations.

**Fix:** both TWSE and TPEx must independently provide at least 100 ranked stock/ETF rows before a fresh snapshot replaces last-known-good. Cross-exchange session-date conflicts or date regressions also retain last-known-good instead of publishing mixed-session data.

### 5. Five-minute market-core refresh could cancel a healthy slower run

`update-market-core.yml` runs every five minutes but previously used `cancel-in-progress: true`. If official endpoints became slow, the next scheduled run could cancel a still-valid refresh before publication.

**Fix:** market-core now uses `cancel-in-progress: false`. Correctness wins over discarding an in-flight verified refresh.

## Non-blocking limitations still intentionally present

- Individual asset detail still assembles several supplementary datasets before every section is complete. This is a performance/UX improvement opportunity, not a current correctness failure.
- **15 分鐘 K 線**仍屬來源相依的**部署後、非阻擋**能力；沒有可信來源時必須顯示不可用／過期狀態，**不得偽造** K 棒。
- Fundamental/financial coverage is source-dependent and should remain explicitly incomplete where official/verified fields are unavailable.
