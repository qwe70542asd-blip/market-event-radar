# v11.4.34 release audit

## 必查項目

1. `scripts/cleanup_repo.py --check` 必須通過；release tree 不得含 `scripts/.github`、`scripts/assets`、`scripts/data`、`scripts/tests`、`scripts/scripts` 等巢狀 repository 副本。
2. 成交金額歷史 backfill 必須逐月工作，不得因整體 row count 足夠而漏掉中間整月；部署後第一輪 v11.4.34 必須能突破同日 v11.4.32 的 backfill stamp，重新檢查缺月。
3. 同一 session 若只有 TWSE component，不得標成完整台股成交額；有 verified TWSE+TPEx quote sum 時應優先採用完整合計。
4. 5／20／60 日平均只能使用 complete total；`volume_history_complete` 必須反映近期 session 完整性，不得只靠總筆數變綠。
5. `tw-market` 與 `market-volume-history` 的交易日期不得是週末／未來日期；quote date 必須等於 verified trading date。
6. TPEx ETF 官方名單失敗時，fallback 必須按交易所獨立處理；TWSE 成功不得阻止 TPEx last-known-good ETF whitelist 回復。
7. `stock-basics` 的 `industry`／`industry_name` 不得洩漏 `9103` 這類純數字證券／舊代碼；無法安全轉換時使用保守文字分類。
8. TPEx 董事會股利 parser 必須支援 `董事會擬議日期`、`董事會決議日期`、全形標點與官方公司代號／股利欄位別名；來源有 rows 而 parser 為 0 必須 warning。
9. TWSE／TPEx 歷史除權息 API 若合法回傳空 rows，可視為 healthy empty；非空 rows 卻解析 0 才是 parser warning。
10. BLS fallback 必須只使用官方 schedule；若 GitHub Runner 遭 403，保留 warning／last-known-good，不得偽造發布日期。
11. global market top-level session、price/OHLC date、`market_at` 與最新 candle 不得跨 session 混用。
12. Cloudflare deploy workflow 不得在 job-level `if:` 直接引用 `secrets.*`；未設定 secrets 時必須能安全跳過 optional edge deploy。
13. release verification 除 syntax、unit tests、HTTP smoke 外，必須有真正 Chromium runtime gate，至少驗證首頁無 `pageerror`、月曆 42 格、標題初始化與雙模式切換。
14. Release hygiene 不得包含音訊、暫存檔或編輯器殘留檔。
15. 15 分鐘 K 線仍屬部署後非阻擋資料；沒有可信資料時不得偽造。

## v11.4.34 additional regression gates

- Global-market timestamp integrity compares `market_at_local` against the exchange-local session date; the Asia/Taipei display timestamp may legitimately fall on the following calendar day for U.S. sessions.
- TPEx dividend and historical ex-right/ex-dividend parser variants must accept punctuation and official schema-name changes without guessing a date from unrelated fields.
- TPEx turnover rows with descriptor-style `fields` must parse date and transaction amount; partial single-market totals remain non-complete.
- ETF classification restores `live-assets` first and can use verified asset-master ETF identities if a TPEx fund endpoint changes schema.
- Nested chip `sources` and `history` must not retain weekend/future dates.
- TPEx official institutional/margin/intraday endpoints are attempted independently; upstream failure must degrade visibly rather than erase last-known-good data.
