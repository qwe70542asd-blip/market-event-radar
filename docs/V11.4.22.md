# v11.4.22 App integration hardening

## User-facing changes

- The six index cards are now ordered as TAIEX, Dow Jones, NASDAQ, Philadelphia Semiconductor, S&P 500 and Nikkei 225. KOSPI/KOSDAQ index cards were removed.
- The duplicated top index summary was replaced with a ten-stock, sector-grouped vertical leader ticker.
- Multi-interval K-lines use a published static data channel before attempting a browser-side provider request. The supported periods are 5m, 15m, 30m, 1h, 4h, day, week and month.
- Four-hour candles are grouped by exchange-local session and never cross lunch breaks or trading dates.
- News images render an immediate local topic fallback and replace it only after the remote image loads successfully.
- Event details use structured cards and readable paragraphs instead of a raw one-line announcement block.
- Raw TXT/JSON announcement endpoints are rendered inside the site instead of triggering a download.
- Dividend rows distinguish an officially confirmed zero from an amount that is still pending.
- ETF holdings show official industry names and compare shares with the previous available holdings date.
- Asset-detail data channels are prefetched to reduce the wait after tapping a stock.
- Cryptocurrency assets were removed from the public asset master.

## Pipeline fixes

- Data verification accepts both list and object channel formats.
- Stock industry codes cannot leak security symbols such as `9103` into the industry field.
- News symbols are accepted only when they exist in the full official stock master; stale seed codes such as `8923` are rejected before publication.
- The global-market workflow publishes both the snapshot and multi-interval K-line channels.
- A release-verification workflow checks Python/JavaScript syntax, strict data validation, automated tests and the site through a real local HTTP server on GitHub Actions.

## Runtime note

The GitHub Actions channel provides the reliable static fallback. A deployed edge worker is still required for guaranteed one-minute server-side updates. Without it, the browser refreshes frequently but new backend data follows the GitHub schedule and provider availability.
