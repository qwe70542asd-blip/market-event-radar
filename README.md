# 市場事件雷達 v11.4.11

本版集中修正法人籌碼與 ETF 資料覆蓋判定：搜尋框不再強制補回中文名稱，籌碼通道開始真正抓取資料，ETF 已存在的基金主檔、配息、持股與產業配置也不再被誤判為待補。

## 法人與籌碼

- 搜尋標的時，使用者輸入內容不會被程式改寫。
- 選擇建議後，輸入框只保留代碼，例如 `00981A`。
- 支援 Backspace、Ctrl+A、Enter、Esc 與中文名稱搜尋。
- 優先讀取 TWSE 結構化三大法人、融資融券與當沖資料。
- 官方資料缺漏時，分批補讀 Yahoo 台股法人與資券歷史。
- 每日資料會累積成最近 5～20 日歷史，不再只有單日空欄位。
- 資料抓取失敗時保留最後成功版本，不會發布空白 `tw-chips.json`。
- 完全沒有籌碼資料的標的改為簡潔提示，不再鋪滿大量 `—`。

## ETF 資料覆蓋

資料覆蓋頁現在使用最終整合視圖，不再只檢查單一 JSON：

1. `assets.json` 的官方／內建基金主檔。
2. `etf-details.json` 的 TWSE、MoneyDJ、HiStock 補充資料。
3. `yahoo-details.json` 的 ETF 基本資料、前十大持股與產業配置。
4. `dividend-history.json` 的歷史配息。
5. `data-verification.json` 的來源與可信度狀態。

基金主檔、配息、持股及產業配置只要任一有效來源存在，就不會再錯誤顯示「待補」。持股含產業欄位時，系統也可由持股自動彙整產業配置。

## 優先補齊標的

更新器會優先處理常用與熱門標的，包括：

- 00981A
- 00403A
- 00631L
- 006208
- 0050、0056、00878、00919
- 2330、2317、2454 等大型權值股

完成優先標的後，再依游標逐批累積全市場資料。

## 資料採用原則

- TWSE／TPEx／MOPS、投信或公司正式資料優先。
- Yahoo、MoneyDJ、HiStock 只補官方缺漏並保留來源。
- 官方與第三方資料衝突時，不直接覆蓋官方值。
- 缺值不以 0 代替。
- 券商分點或法人買賣資料不代表最終客戶真實持倉。

## 部署

將解壓後 `market-event-radar` 資料夾內的完整內容提交到 `main`。上傳後建議手動執行：

1. `Update v11.4.11 ETF details`
2. `Update v11.4.11 Yahoo asset details`
3. `Update v11.4.11 Taiwan chips`
4. `Update v11.4.11 assets and audit`

第一次執行會優先補齊 00981A 等常用標的，後續排程再逐批累積全市場。

## 限制

- 第三方網站可能調整 HTML 或限制自動請求；每個通道都保留上一份成功資料。
- 上櫃籌碼在官方結構化來源不足時，會使用 Yahoo 作為參考來源並標示來源。
- ETF 每日完整持股、正式淨值與受益人資料仍以投信和交易所公告為準。
- 個人投資組合保存在使用者瀏覽器的 localStorage，不會上傳到伺服器。

## v11.4.11 亞洲總體風險新聞

新增日本、韓國、中國與亞洲金融風險的繁體中文文字新聞通道；不採用訪談節目或影音內容。
