# 市場事件雷達｜v11.2.8 全市場完整資料稽核版

本版將資料修正方式由「抽查代表股票」改成「逐筆掃描全部上市、上櫃股票與 ETF」。

## 日曆顯示

事件彈出視窗中的股票代碼、事件標題、摘要與時間文字已取消底線。滑鼠移入、鍵盤聚焦與已瀏覽狀態也不會重新出現底線。

## 全市場資料稽核

`assets.json` 內每一筆台灣股票與 ETF 都會建立一筆稽核結果，不抽樣、不跳號。

輸出檔案：

- `data/asset-audit.json`：全部標的及全部欄位結果。
- `data/asset-audit-seed.js`：GitHub Pages 靜態備援。
- `data/asset-audit-failures.csv`：尚未補齊的股票、ETF、欄位與原因。
- `data/asset-update-status.json`：更新是否成功、重試次數與錯誤資訊。

每檔股票檢查公司主檔、財務指標、最近 12 個已完成季度、股利、行情、法人、信用交易、當沖、新聞與公告。

每檔 ETF 檢查基金主檔、發行公司、經理人、類型、追蹤指數、策略、日期、保管機構、股利、行情、法人、信用交易、當沖、新聞與公告。

## 財報處理

- 財報目標由最近 4 季提高為最近 12 個已完成季度。
- 從最近已結束的季度開始，不會誤抓尚未完成的季度。
- 上市與上櫃歷季財報改為平行取得。
- 官方請求加入有限次重試與逾時。
- 金融業不強迫套用一般產業流動比率。
- EPS 非正數時，本益比標示「不適用」，不算成抓取失敗。
- 尚未申報、來源失敗、解析格式不同及真正不適用會分開紀錄。

## 失敗與逾時處理

GitHub Actions 單次工作限制在 14 分鐘內。資產更新最多執行兩次，每次都有硬性時間上限。第二次仍失敗時：

1. 恢復上一版成功資料。
2. 不讓單一來源清空整個市場資料。
3. 繼續稽核其他股票與 ETF。
4. 將未解決項目輸出到 `asset-audit-failures.csv`。
5. 在資料覆蓋頁統計成功、部分完成與未解決數量。

逐檔各等待 15 分鐘不適合全市場：若約 2,000 檔各等 15 分鐘，單輪會超過 500 小時。本版改為批次取得官方資料，再對全部標的一筆一筆核對，來源操作受 14 分鐘工作上限保護。

## 資料覆蓋頁

`coverage.html` 已改成全市場完整稽核頁：

- 顯示實際稽核標的總數。
- 分別統計股票與 ETF。
- 顯示完整、部分完成與未解決數量。
- 每個欄位使用自己的適用分母。
- 可搜尋代碼或名稱。
- 可篩選股票、ETF、完整、部分與未解決。
- 點擊標的後在原頁展開全部欄位與缺漏原因。
- 不再以少數代表股票推測全市場。

## 使用者介面整理

- 一般使用者導覽列移除「資料狀態」。
- 新聞來源健康狀態預設隱藏。
- 管理診斷仍可直接進入 `data-status.html`。
- 新聞來源診斷可在新聞網址後加上 `?admin=1` 查看。

## 上傳

1. 解壓縮 ZIP。
2. 將資料夾內全部檔案覆蓋 GitHub Desktop 倉庫根目錄。
3. Commit：`全市場完整資料稽核 v11.2.8`
4. Push origin。
5. 等待 `Update v11.2.8 assets financials and full audit` 完成。
6. 等待 Pages 部署完成。
7. 網站按 `Ctrl + F5`。
8. 開啟 `coverage.html` 查看實際全市場統計與未解決清單。

本地封裝環境無法取得 GitHub `live-assets` 的完整線上市場檔，因此壓縮包內只能驗證完整巡覽邏輯及內建種子標的。上傳後 GitHub Actions 會以完整 `assets.json` 執行全市場稽核，產生實際數量與失敗報告。
